# Family Move Support

転勤によって変わる家族の仕事・保育・住まいを、一つの生活移行計画にまとめるプレゼン用MVPです。SPEC.mdに沿って作成しています。

## 背景

大学生向けビジネスコンテスト **CAREER ROOKIES GP 2026** の本選準決勝に向けて、最初に考えた案「**転勤コンシェルジュ**」のプレゼン用 MVP です。この案は発表しておらず、チームの提案は最終的に「FRONTIER BASE」になりました(LP: [careerrookies2026-frontier-base-lp](https://github.com/koubeyapurin/careerrookies2026-frontier-base-lp))。

- 森平(koubeyapurin)が1人で作りました。仕様書 [SPEC.md](SPEC.md) は森平が書き、それをもとに AI(Codex など)に実装させ、テスト(Vitest・Playwright)・CI(GitHub Actions)・GitHub Pages での公開まで整えました
- 大会の公式ページ: https://gp.careerrookies.com/

## 公開サイト

- デモ：https://koubeyapurin.github.io/family-move-support/
- ソース：https://github.com/koubeyapurin/family-move-support

`main`ブランチへpushすると、GitHub ActionsでLint・単体テスト・ビルドを実行し、成功後にGitHub Pagesへ自動公開します。公開の実行結果はリポジトリのActionsタブで確認できます。

公開サイトも保存先は各自のブラウザ内です。入力内容をサーバーへ送信しません。ローカル版と公開版の保存データは別々です。

## 起動

Node.js 20.19以上、22.12以上、またはそれ以降のバージョンを使用してください。

```bash
npm install
npm run dev
```

表示されたローカルURLをブラウザで開いてください。通常は http://127.0.0.1:5173 です。

WindowsのPowerShellで実行ポリシーのエラーが出る場合は、`npm`の代わりに`npm.cmd`を使用してください。システムの実行ポリシーを変更する必要はありません。

```powershell
npm.cmd install
npm.cmd run dev
```

本番ビルドを確認する場合：

```bash
npm run build
npm run preview
```

バックエンド、アカウント登録、APIキーは不要です。パッケージをインストールした後は、インターネット未接続でもローカルサーバーから利用できます。画像・アイコン・スタイルも外部サービスに依存しません。

## 3分のデモ手順

1. ダッシュボードを開き、佐藤家のプロフィールと「推奨B案・進捗46%」を紹介します。
2. 「Family Move Check」で、ご家族の状況と5段階の優先順位を確認します。変更する場合は、最後の「保存してシナリオを比較する」で反映します。
3. 「シナリオ比較」でA・B・Cの暮らし方を比較します。初期状態はB案がおすすめです。
4. 「条件が変わったら？」を開き、妻の関西異動を「可能」、保育園受入見込みを「高」にします。
5. 「新しい条件で再計算」でA案へ変わります。「更新されたFamily Move Planを見る」で、バージョン・更新理由・住居タスクの変化を確認します。
6. 「やること」で妻の異動確認を完了にすると、進捗が46%から54%になります。再読み込みしても保持されます。
7. メッセージを開き、JTBコンシェルジュの伴走を紹介します。
8. もう一度デモする場合は、ヘッダーの「デモを初期状態に戻す」を使用します。

基本デモはFamily Move Checkで保存せず、閲覧してから比較画面へ進むと、Replan後の表示がちょうどPlan v2になります。入力内容の保存でもプランが更新されるため、その場合はバージョンがさらに進みます。

## 実装した機能

- 家族プロフィール・推奨案・未確定事項・進捗・タスクをまとめたダッシュボード
- サンプル入力済みの3ステップFamily Move Check
- 優先度の重み付けと条件補正による3案比較・Replan
- 推奨理由、Must / Want、リスク、スケジュール、担当・期限、更新履歴を含むFamily Move Plan
- 家族での方針確認、勤務先への共有範囲設定、文書風プレビュー
- タスクの完了・取り消し・絞り込み、全タスク完了後のTransition Complete
- 固定会話とローカルのデモ送信を備えたコンシェルジュドロワー
- LocalStorageへの保存、破損データの初期化、保存不可時の画面内案内、デモリセット
- PC・タブレット・スマホ対応、モーダルのフォーカス制御、Escapeで閉じる操作

## デモデータと計算

- 初期スコアはA=70、B=77、C=75。SPEC.mdの計算式をそのまま使用しています。
- 妻の異動が「可能」、保育園見込みが「高」の場合はA=87となり、A案を推奨します。
- 進捗は初期46%、タスク1件につき+8%。生活移行完了の操作でのみ100%になります。
- Plan v1の日付は2026/10/08、更新時はデモ内の基準日2026/10/12を使用します。
- 介護と持家の有無はPlanの確認事項に反映します。判定APIなどは使用しません。
- `family-move-support-demo-v1`キーで、このブラウザ・このオリジン内だけに保存します。
- 入力中のFamily Move Checkは最終ステップの保存時に反映します。メッセージのデモ送信はドロワーを閉じると消えます。
- 共有設定はデモ表示のみです。企業への送信、実チャット通信、PDF生成は行いません。

## チェック

```bash
npm run build
npm run lint
npm test
npm run test:e2e
npm run format:check
```

E2Eテストは端末にインストール済みのGoogle Chromeを使用します。開発サーバーはテストで自動起動します。テスト結果のスクリーンショットは`test-results/`に保存します。

単体テストでは推奨の切り替え、評価値の範囲、優先順位の反映、進捗、未確定事項、保存復元・破損データへの対応を確認します。E2Eではデモの全導線、リロード、リセット、入力編集、完了・共有設定、スマホ表示、オフライン時の画面操作を確認します。

## 構成

```text
src/
  App.tsx                 アプリ全体の状態・画面切り替え・保存
  data.ts                 型定義とデモデータ
  index.css               デザイントークン・各画面・レスポンシブ
  components/             共通UI、タスク、各種パネル、SVGイラスト
  views/                  5つのメイン画面
  lib/recommendation.ts   推奨・進捗・条件整理の純粋関数
  lib/storage.ts          保存と復元時の検証
tests/                    Playwrightによるブラウザ操作テスト
```

React、Vite、TypeScript、Tailwind CSS、Lucide Reactを使用しています。状態管理はReactのみで完結します。画面遷移はローカルstateを使い、再読み込み時には保存済みデータを読み込んだダッシュボードに戻ります。
